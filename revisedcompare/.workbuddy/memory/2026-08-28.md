**修复方式**：整体重写 index.html（保留原 UI/CSS）。

**核心实现**（可复用要点）：
1. **diff 引擎**：短文本（<16 字符）直接字符级 LCS（Array.from 处理代理对）；长文本用空白不敏感的锚点对齐递归切分。
2. **修了原版锚点空白 bug**：`_findPrefixInTarget`/`_findAnyAnchor` 原来用归一化长度切 raw 字符串会错位丢字；现在返回 pos/rawLen/srcLen 原始长度（用 `_mapNormToRaw` 换算），equal 段取新文本原文，删除段取选区原文。
3. **写入路径**：首选 `range.insertOoxml(fragment, Word.InsertLocation.replace)`；回退 `insertFileFromBase64`（完整 DOCX，JSZip 生成，含 sectPr）。w:ins/w:del 的 w:id 用 100000+随机数起步保证全文档唯一；author=修订式粘贴；date=ISO8601。

5. 新增"无差异不写入"分支；剪贴板读取带 window.clipboardData 旧接口回退。

**验证**：node --check 语法通过；7 组 diff 用例全 PASS（含长文空白锚点、多段、emoji）；生成 OOXML 用 Python ElementTree 校验 well-formed、w:ins/w:del id 唯一。

## 修复2（17:15）：insertOoxml 注入修订被 Word 静默"接受"，实际是整体替换 → 改用 trackRevisions

**问题**：用户实测点击执行后文本被整体替换成新文本，看不出修订。根因：Office.js 的 `insertOoxml` 对 w:ins/w:del 修订标记**无官方支持保证**，多数 Word 版本会静默接受修订（等同直接替换）。手工注入修订标记的路子不可靠。

**修复方式（已验证）**：
1. **主路径改为 Word 官方修订机制 `document.trackRevisions`**：写入前保存原值→置 true→执行文本操作（Word 自己生成 w:ins/w:del）→恢复原值。
2. **段落级 diff `buildParaOps(origText, newText)`**：按 `\n` 拆段做 LCS（段数组 O(n*m)），回溯折叠为"原段视角"操作：`ops[原段索引] = {type:'equal'|'delete'|'replace', newText, insertAfter:[..]}` + `headInsert:[..]`（插在选区第一段前）。delete 后紧跟 insert 自动折叠成 replace。
3. **`writeRevisionsTracked` 执行**：`sel.paragraphs` 取选区段落（load items），**从后往前**逐段：headInsert 用 `items[0].insertParagraph(..., 'before')`；insertAfter 链式 `insertParagraph(..., 'after')`；replace 用 `insertText(newText, 'replace')`；delete 用 `para.delete()`。从后往前避免索引漂移。
4. **对齐校验**：execute 第一步同时 `ctx.load(paras, 'items/text')`，校验段落数一致且每段 normalize 后与 sel.text 拆分一致；不一致（选区部分覆盖段落）→ 回退 `writeWholeSelectionTracked`（trackRevisions 下整体 insertText Replace，Word 标记整段删+插）。段落级写入抛错同样回退整体替换。
5. **insert 模式**：`writeInsertTracked`，trackRevisions 下光标处 `insertText(newText, 'after')`。
6. 删除旧 `writeRevisionsToSelection`（insertOoxml 路径不再使用）；`buildTrackedOoxml`/`buildTrackedDocxBlob` 保留（下载 DOCX 兜底）。
7. **manifest 增加 `<Requirements><Sets><Set Name="WordApi" MinVersion="1.3"/></Sets></Requirements>`**（trackRevisions 需 WordApi 1.3），放 VersionOverrides 内 Hosts 之前。

**踩坑记录**：
- `if (op.type==='equal') continue` 会把带 insertAfter 的 equal 段和 k===0 的 headInsert 一起跳过 → 插入段落永不执行。必须改为"无任何操作才 continue"，headInsert 处理提前到 continue 判断之前。
- Word 段落对象是稳定引用（插入/删除前面段落不影响其有效性），从后往前处理 + 引用定位是安全的。

**验证**：10 组段落链路用例全 PASS（单段修改/多段修改/中间插段/删段/开头插段/整段重写/空段/无差异/段尾空格/长段落），mock 用对象引用定位模拟 Word 引用语义；语法检查 OK；字符级 diff 7 组回归全过；aligned 分支 4 组用例 PASS；manifest XML 校验 well-formed。

**行为变化**：修订粒度从"字符级"变为**段落级**（改动段落整段显示删除线+下划线，未改动段落原样）。对合同/章程/年报条款级修改足够实用；受 Word JS API 无字符偏移定位能力限制，段落内字符级修订无法用 trackRevisions 实现。视图提示：需在「审阅 → 所有标记」查看。
